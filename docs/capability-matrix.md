# Capability Matrix

> **Measured on:** 2026-09-05 against `main` and the production deployment. Tracking issue: [#9720](https://github.com/Tristan578/project-forge/issues/9720). Readiness review: [#9714](https://github.com/Tristan578/project-forge/issues/9714).

This is the accurate statement of which capability works today through which entry point. It replaces the README's former claim that "every capability" is exposed and controllable via MCP. Every row below carries one status per entry point; a status that is not `proven` names the issue that tracks the gap, and a status of `excluded` says why in the Notes column.

The four entry points:

| Column | Meaning |
|--------|---------|
| **Human/UI** | A person using the editor's panels, inspectors and dialogs. |
| **In-app AI** | The built-in chat assistant and the game-creation pipeline, which call manifest commands through `web/src/lib/chat/executor.ts`. The model is offered every manifest command with a `:write` scope plus the `query` category (`getChatTools()`). |
| **Scripting** | A user-authored game script calling the `forge.*` API (`web/src/lib/scripting/forgeTypes.ts`), which dispatches only the names in `scriptAllowlist.ts`. |
| **External MCP** | An MCP client (Claude Code, Claude Desktop, any MCP host) attached to the editor through `mcp-server/` and its relay. |

## Legend

| Status | Definition |
|--------|------------|
| `proven` | Exercised end to end against a running build, with the evidence named in Notes: a Playwright spec in the CI `@engine-smoke` gate (`web/playwright.engine.config.ts`), or a by-hand check on production on the date in the header. Nothing else earns this word. |
| `implemented-unverified` | The code path exists and unit or parity tests pin it, but there is no end-to-end evidence against the shipped artifact. The launch-readiness review that owns closing this gap is [#9714](https://github.com/Tristan578/project-forge/issues/9714). |
| `partial` | Part of the row works through this entry point and part does not. Notes says which part; the issue names the gap. |
| `unavailable` | Cannot be used through this entry point today, whatever the code says — a missing key, a missing gate, a missing engine arm. The issue names the fix. |
| `excluded` | Deliberately not offered through this entry point. Notes says why. This is a design decision, not a gap. |

## Facts this matrix reflects (verified 2026-09-05)

- **Production has no `PLATFORM_*` generation keys** ([#9117](https://github.com/Tristan578/project-forge/issues/9117)). Every generation capability served by the platform's own key is `unavailable` for platform users. Users who add their **own** key under Settings → API Keys (BYOK: Anthropic, Meshy, Hyper3D, ElevenLabs) can still generate through that provider; each row says when that applies. There is no BYOK path for OpenAI, Replicate or remove.bg, so image, sprite and background removal have no working path at all.
- **Music cannot be provisioned** ([#9522](https://github.com/Tristan578/project-forge/issues/9522)): `PLATFORM_SUNO_KEY` cannot be obtained and BYOK Suno keys cannot be either. Music is `unavailable` through every entry point. [PR #9725](https://github.com/Tristan578/project-forge/pull/9725) refuses `generate_music` before any token is deducted and hides the in-product entry points; this matrix does not duplicate that work.
- **External MCP cannot reach production** ([#9722](https://github.com/Tristan578/project-forge/issues/9722)): `NEXT_PUBLIC_MCP_BRIDGE` is absent from the production build, so `mcpBridgeEnabled()` (`web/src/lib/mcp/bridgeOptIn.ts`) is false and no external client can attach. Every External MCP cell is `unavailable` until that decision lands. In a local build — or a production build made with `NEXT_PUBLIC_MCP_BRIDGE=true` — the relay attaches to a tab opened with `?mcp=<token>` after the in-tab consent prompt and executes through the same handler registry as the in-app AI, so the In-app AI column is the ceiling for what external MCP could do there. That local path is itself unverified end to end.
- **The public MCP reference is down**: `docs.spawnforge.ai/mcp` returns 500 ([#9718](https://github.com/Tristan578/project-forge/issues/9718), fix in progress).
- **Phantom script commands** ([#9284](https://github.com/Tristan578/project-forge/issues/9284)): 16 names in `SCRIPT_ALLOWED_COMMANDS` have no engine arm: `set_velocity`, `set_velocity2d`, `set_angular_velocity2d`, `set_music_intensity`, `set_music_stems`, all four sprite-animation names (`play_sprite_animation`, `stop_sprite_animation`, `set_sprite_anim_speed`, `set_sprite_anim_param`), all four `camera_*` names, `stop_skeletal_animation2d`, `set_ik_target2d` and `vibrate`. A script calling one gets no error and no effect, because `dispatchCommand` returns void. Rows whose scripting surface includes one of these are `partial (#9284)`, or `unavailable (#9284)` when every name is a phantom.
- **Manifest size**: `mcp-server/manifest/commands.json` holds **351** commands across **41** categories, 282 public and 69 internal (`jq '.commands | length' mcp-server/manifest/commands.json`). Command *registration* is 351/351 (`web/src/stores/slices/__tests__/commandArmParity.test.ts`, `web/src/lib/chat/__tests__/manifestHandlerParity.test.ts`); registration is not runtime parity, which is why most cells below are `implemented-unverified` rather than `proven`.

## How this file is checked

`web/src/lib/config/__tests__/capabilityMatrix.test.ts` runs in the web unit-test gate and reads this file. It fails when:

- a `PROVIDER_CAPABILITIES` entry has no `generation:<capability>` row, or a manifest category has no `commands:<category>` row;
- a row names a capability or category that no longer exists;
- any of the four entry-point cells is not exactly one of the five statuses, optionally followed by ` (#issue)` or ` (#issue, #issue)`;
- a `partial`, `unavailable` or `implemented-unverified` cell carries no issue reference, or a `proven` cell carries one (evidence for `proven` belongs in Notes);
- a row with an `excluded` cell has an empty Notes column;
- the legend stops defining one of the five statuses;
- `generation:music` is anything but `unavailable (#9522)` in every column, or any External MCP cell is anything but `unavailable (#9722)` — those pins are removed in the same change that closes the issue;
- `apps/docs/data/capability-matrix.md`, the copy the docs site renders at `/capability-matrix`, is not byte-identical to this file.

The walk fails closed: an unreadable file, zero rows, or a header missing one of the four columns is a failure, never a pass. To add a row, copy an existing one and change every cell you can stand behind. To promote a cell to `proven`, name the CI-run spec or the production check in Notes.
