**`thinking: {type:'enabled', budgetTokens}` returns HTTP 400 on Claude Opus 4.8** — model-side, no package bump
`web/src/lib/ai/spawnforgeAgent.ts:177-179` emits that literal gated on `isDirectBackend`, never on model; `models.ts:33` sets `AI_MODEL_PREMIUM = 'claude-opus-4-8'`. Claude 4.7+ rejects `type:"enabled"` outright. Fires when the direct backend resolves (primary route with no gateway key; circuit-breaker failover otherwise) AND the Pro/creator extended-thinking toggle is on. Deep-tier generations are unaffected (`thinking` defaults false). `aiSdkAdapter.ts:152` is dead (`resolveChat()` has no production callers). On the gateway route the same toggle is a silent no-op — no anthropic providerOptions are sent and Opus 4.8 does no thinking without explicit `{type:'adaptive'}`.
**Action:** branch on model family, not backend. Emit `{type:'adaptive'}` (+ `display:'summarized'` if reasoning streams) for 4.6/4.7+; reserve `{type:'enabled', budgetTokens}` for Haiku 4.5 and earlier. `@ai-sdk/anthropic@4.0.41` already forwards the adaptive variant — no dep bump. **Constraint (verified separately):** do NOT blanket-swap to `adaptive` — Haiku 4.5 rejects it with a 400, and `effort` at `spawnforgeAgent.ts:181-183` is likewise model-blind and rejected on Haiku. Build a `thinkingModeFor(modelId)` + `supportsEffort(modelId)` table in `models.ts`.
**Cost:** none.
