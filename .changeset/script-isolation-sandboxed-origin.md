Add an opt-in isolation boundary for in-editor game scripts (#8700). With `NEXT_PUBLIC_SCRIPT_ISOLATION=sandboxed-origin` set at build time, scripts run in the same worker code but inside a hidden `sandbox="allow-scripts"` iframe with its own `connect-src 'none'` policy, so a script that escapes the name shadowing runs in an opaque origin, where it cannot read the app's cookies or storage, and cannot make any network request, whether or not the network globals were revoked first. The default (`revoke`, or any value other than the exact strings `sandboxed-origin` / `ast`) is unchanged. `ast` is reserved and currently runs the sandboxed transport with a plain-language notice in the script console. If the sandbox cannot start, Play stops with a single message chosen by why: when the browser refuses to run the sandboxed worker, the creator is told their scripts can't run in this browser with the current editor settings (and that a different browser might work), with no retry advice, because retrying cannot help; when the sandbox simply did not answer in time, or its code failed to load, the creator is told to press Play again or reload the editor.

Browser support: in CI the sandboxed transport runs scripts in Chromium and Firefox, and does not run them in WebKit (Safari). There the worker fails to start, so it fails closed: Play stops with the "can't run in this browser" message and nothing is sent, and Safari users cannot run game scripts at all with the flag on. Do not enable the flag for production users until WebKit support exists.
