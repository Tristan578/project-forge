Migrated `web/vercel.json` to a typed `web/vercel.ts` and added `@vercel/config` as a devDependency of `web` (its only use is an `import type`, erased at compile time — which is required, not incidental: the Vercel CLI compiles `vercel.ts` on the CD runner before `vercel deploy`, and the staging deploy job runs no `npm ci` first, so a value import from `@vercel/config` would fail the deploy; `vercelConfig.test.ts` pins that every import stays type-only). Its transitive `@vercel/routing-utils@6.6.0` pins an exact `path-to-regexp@6.1.0` that carries GHSA-9wv6-86v2-598j (backtracking regular expressions, high), so the root `package.json` gains a version-selector override — `"path-to-regexp@6.1.0": "6.3.0"`, listed before the repo-wide `"path-to-regexp": ">=8.4.0"` rule so it matches that exact-pinned edge first — that retires only that nested copy to the patched 6.x release (the same 6.3.0 routing-utils already ships as `path-to-regexp-updated`), without touching the repo-wide rule or the audit allowlist. A scoped `"@vercel/routing-utils": { "path-to-regexp": ... }` form was rejected: npm 11.19 treats the resulting override subtree as incomparable with the pre-existing `@eslint/eslintrc` scoped subtree, and because their flattened rulesets carry non-intersecting `path-to-regexp` rules, the `uri-js` node both subtrees share reports INVALID (Lockfile Sync stage 1). npm also propagates overrides only along dependency edges, never through workspace links, so the same `@vercel/config` range is additionally declared in the root `package.json` devDependencies purely to carry the override into that subtree; both declarations must stay on the same range. Deploy behaviour is unchanged: every value the JSON declared is preserved verbatim — `framework: nextjs`, the `cd .. && npm ci && npm run build --workspace=packages/ui` install command, `npm run build`, the `.next` output directory, the `iad1` region, `git.deploymentEnabled: false`, and the `/api/cron/health-monitor` cron on `*/15 * * * *`. The gain is that a typo'd or removed property now fails `tsc --noEmit` instead of silently misconfiguring the deploy.
