Migrated `web/vercel.json` to a typed `web/vercel.ts` and added `@vercel/config` as a devDependency of `web` (its only use is an `import type`, erased at compile time; Vercel evaluates `vercel.ts` at build time, where devDependencies are installed). Its transitive `@vercel/routing-utils@6.6.0` pins an exact `path-to-regexp@6.1.0` that carries GHSA-9wv6-86v2-598j (backtracking regular expressions, high), so the root `package.json` gains a scoped override — `"@vercel/routing-utils": { "path-to-regexp": "6.3.0" }` — that retires only that nested copy to the patched 6.x release (the same 6.3.0 routing-utils already ships as `path-to-regexp-updated`), without touching the repo-wide `path-to-regexp >= 8.4.0` override or the audit allowlist. Deploy behaviour is unchanged: every value the JSON declared is preserved verbatim — `framework: nextjs`, the `cd .. && npm ci && npm run build --workspace=packages/ui` install command, `npm run build`, the `.next` output directory, the `iad1` region, `git.deploymentEnabled: false`, and the `/api/cron/health-monitor` cron on `*/15 * * * *`. The gain is that a typo'd or removed property now fails `tsc --noEmit` instead of silently misconfiguring the deploy.
