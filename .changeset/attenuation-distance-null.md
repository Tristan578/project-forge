Fixed a bug where a scene with an untouched (default) material failed to load. A material's `attenuationDistance` defaults to infinity, which JSON stores as `null`, and the loader rejected its own output (`invalid type: null, expected f32`). The engine now reads that `null` back as infinity at the field level. Nothing about the saved scene format changes: `null` stays the encoding of the default, keys and number formatting are untouched, and live editor updates (material inspector, entity queries) keep their `number | null` contract. A rolled-back engine still cannot open a scene with a default material, exactly as before this fix.

Loading stays tolerant, so no scene that opened before this change is refused by it. A negative or overflowing `attenuationDistance` (which older engines loaded as written, and `update_material` used to store unchecked) now loads as infinity, with a warning in the engine log. A non-numeric value such as a string is still refused, as it always was. The live `update_material` command is strict: a negative or non-finite number is refused with "attenuationDistance must be a finite number >= 0, got X; send null for infinity", so no new scene can carry one. An explicit `null` on `update_material` now sets infinity explicitly (the inspector's "Infinite" checkbox sends it), and the MCP manifest types the field as `number | null`. `update_material` still replaces the whole material, so an omitted field resets to its default.

When the engine refuses a scene, its reason is now shown in plain words in the save-lockout notice and in the checkpoint-recovery error. The `Invalid scene file:` prefix and serde's line and column are dropped, and the checkpoint error ends with "Reload the editor and try again." The AI `validate_scene` tool still receives the engine's raw text, which it needs to repair the scene. Relayed text is capped at 512 characters with a visible `… [truncated]` marker, because the engine's error can quote the offending scene value and a remixed scene is another person's input. A long unbroken value in the lockout notice now wraps instead of overflowing.
