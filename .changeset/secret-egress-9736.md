Stop upstream provider text reaching clients, and put the control on the response path itself (#9736). The generation clients fold the upstream **response body** verbatim into the thrown error (`Meshy status error (401): <body>`), and twelve routes returned that error's `message` in their response — so on the platform path, where the credential in play is the platform's rather than the user's, a provider that echoes key material in an auth-failure body would hand a platform secret to any signed-in user. Those routes now return fixed, actionable text and send the detail to Sentry; `/api/game/decompose` still returns its safety-filter reason, narrowed by a typed `PromptRejectedError` rather than by a message prefix any upstream error could also produce.

**The guarantee is a runtime chokepoint, not a lint rule.** `withEgressGuard` (`web/src/lib/security/egressGuard.ts`) wraps all 102 App Router handlers and, before a response is returned, redacts the body (JSON parsed and re-serialised, other text redacted as text), every response header value, every `Set-Cookie`, and the `Location` of a redirect. That closes the header, cookie and redirect channels structurally — no dataflow analysis is involved. However the body was assembled, it passes through one function. Enforcement that every route is wrapped is a SHAPE check a parser can answer with certainty: `egressGuardCoverage.test.ts` walks every `src/app/**/route.ts` through the TypeScript parser and names any exported HTTP method that is not a `withEgressGuard(...)` call, failing closed on zero files.

Three review boards defeated three successive static designs before this. The first enumerated how a body was ASSEMBLED and lost to eleven ordinary shapes. The second forbade the SITE and lost to sinks the list did not name. The third tracked the caught value and reported where it CROSSED OUT of the catch scope, claiming that crossing out is a closed set — and lost to one-liners: `const sink = cache; sink.set('last', err.message)` aliasing a module-scoped Map, `const R = NextResponse`, a hoisted `function detail() { return String(err); }`, a tagged-template SQL write, and `yield`. The escape check compared NAME scope against reachability, so a single `const` silenced every escape the earlier boards had pinned. A hand-written static analysis over an open-ended language is the wrong primitive for a property that has to hold.

`spawnforge/no-raw-response-in-catch` is KEPT and demoted to what it is: early feedback in the editor for the common shapes, explicitly not the guarantee. Its docblock now says so and lists what it cannot see (`Promise.allSettled`, callback parameters, a tainted receiver, the non-throwing path, name collisions across nested scopes, the 12-pass fixpoint cap). The pass-3 shapes above are nonetheless closed and pinned by named RuleTester cases: receiver locality is now decided by what a binding RESOLVES to rather than by where its name was declared, local and namespace aliases of the raw constructors are resolved, the site ban is unconditional (a single `typeof err` in the arguments used to suppress it), tagged templates and `yield` are classified, and a hoisted function or class that closes over the caught value is tainted.

Redaction is also now genuinely on every response rather than only where a route remembered a sanctioned constructor: 126 catch-path responses across 77 files go through `createErrorResponse` / `apiError` / `redactedJson`, and the guard runs underneath all of them. `noRawResponseInCatchCoverage.test.ts` asks ESLint's own `calculateConfigForFile` whether the rule is switched on for every module that constructs a response, failing on zero matches. Widening the glob surfaced three real sites, all fixed. Separately, `/api/bridges/aseprite/execute` forwarded its BridgeResult verbatim on the SUCCESS path — `stdout`, `stderr` and an `error` built from `stderr`, carrying the child_process command line and the temp Lua script path — and now returns only `outputFiles`/`metadata`.

Two defects the runtime tests found, both real. **Percent-encoding defeated every credential shape**: they are anchored on a word boundary, and in `?e=invalid%20key%20sk-ant-AAA` the character before `sk-ant-` is the `0` of `%20`, so a redirect `Location` and a `Set-Cookie` value — the two channels the guard exists to close structurally — were passing the key through verbatim. `redactSecretsAll` gains an opt-in `percentAware` mode that matches a decoded view and splices the placeholder back into the raw string at mapped offsets, leaving the surrounding encoding byte-for-byte intact; it is off by default, so the Sentry path and the response constructors are unchanged. **Thirteen regex passes per string leaf** cost +1.088 ms per request on a 13 KB listing body once the guard put redaction on every response; the shapes are now derived into one alternation that preserves their documented precedence, and the same body costs +0.339 ms. A typical error envelope costs +0.087 ms. `redactSecretsAll` also derives the environment secret list once per response instead of once per header value.

`redactSecrets` itself gains shapes for Meshy, ElevenLabs (`sk_` + hex — the OpenAI pattern is hyphenated and could never match it) and GitHub fine-grained PATs; an unanchored name pattern so `GITHUB_MODELS_PAT`, `ASSET_R2_ACCESS_KEY_ID` and `PGPASSWORD` are covered; a redacted marker at the depth bound instead of emitting the sub-tree unchanged; `Date`, `Error`, `Map` and `Set` preserved instead of collapsing to `{}`; `null` left as `null` instead of becoming `""`; upper bounds on every quantifier, matching the linear-matching invariant `sentryConfig` documents; and the environment list memoised behind a fingerprint that still invalidates under `vi.stubEnv`.

Two gaps are stated rather than implied, and pinned as gaps by tests so nobody reads silence as coverage: a 2xx `text/event-stream` body streams through unredacted (buffering it would stall `/api/chat`, which streams as its core product path — its headers are still redacted, and any status >= 400 is always buffered and redacted), and an uncaught throw from a handler is re-thrown rather than converted, so Next.js renders its own error response and `instrumentation.onRequestError` and Sentry keep firing.

Also removes `src/lib/api/response.ts`, whose second exported `apiError` had a different envelope and no redaction, and makes the eight status-route messages reach the user. Two halves were needed: `useGenerationPolling` saw `!response.ok` and threw before reading the body, so a persistently failing status route showed a stalled progress bar for five minutes and then a bare "Generation timed out" — and reading the message was still not showing it, because `GenerationStatus` renders only while a job is pending/processing/downloading, so marking the last job failed unmounted the sole renderer at the instant the message was written. Every failure path now raises an error toast, asserted in `useGenerationPolling.test.ts`.
