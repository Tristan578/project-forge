Stop upstream provider text reaching clients, and enforce it with a lint rule (#9736). The generation clients fold the upstream **response body** verbatim into the thrown error (`Meshy status error (401): <body>`), and twelve routes returned that error's `message` in their response — so on the platform path, where the credential in play is the platform's rather than the user's, a provider that echoes key material in an auth-failure body would hand a platform secret to any signed-in user. Those routes now return fixed, actionable text and send the detail to Sentry; `/api/game/decompose` still returns its safety-filter reason, narrowed by a typed `PromptRejectedError` rather than by a message prefix any upstream error could also produce.

Enforcement is a local ESLint rule, `spawnforge/no-raw-response-in-catch` (`web/eslint-rules/`), and it is an ALLOWLIST rather than a list of forbidden sinks. Two earlier designs were each defeated by a review board in one sitting. The first enumerated how a body was ASSEMBLED (a source scan) and lost to eleven ordinary shapes. The second forbade the SITE — `.json`, an assignment to an outer binding, an argument to a sanctioned constructor — and lost to sinks the list did not name: the RETURN VALUE of a catch scope (`.catch((e) => e.message)`, with the response built at the call site), a header set on a SANCTIONED constructor's result, a `redirect` whose URL carries the text, a receiver rooted in a call (`getDb().update(x).set({ e: err.message })`), a stream's `enqueue`, `Object.defineProperty`, a destructuring assignment, the second name of a destructured catch param, a for-of binding, the two-argument `.then(ok, onRejected)`, and `import { NextResponse as NR }`. The sink space is as unbounded as the assembly space.

So the rule tracks the caught binding and every value derived from it, and reports wherever that value CROSSES OUT of the catch scope: returned, written into anything not declared inside the catch, passed to a response constructor, or passed to any call that is not on the sink allowlist. The allowlist (`errorSinks`, `loggerObjects`) is set in `web/eslint.config.mjs` so a reviewer can audit what may consume an error without reading the rule. Derivations are inert and stay quiet. The site ban is kept alongside it, widened to every member of NextResponse/Response and resolved through import bindings, because it catches a response whose body carries upstream text the taint tracker cannot see. The `instanceof` exemption now covers only the narrowed error's own message-shaped properties, not `err.cause.body` and not the error passed whole. Every shape above is a named RuleTester case, each also verified by hand through `npx eslint` on a file under the linted glob, and the rule is mutation-tested: breaking any one branch fails a specifically named case.

That is also what makes `redactSecrets` real: 126 catch-path responses across 77 files now go through `createErrorResponse` / `apiError` / the new `redactedJson`, where previously 89 of 101 route files built error bodies with a raw `NextResponse.json` and the "net" covered none of the routes that had the defect. The rule found two live issues on its first run: `/api/admin/moderation/bulk` returned a database error's message inside a 200 body, and `/api/projects` reads a numeric field off its own error (waived in place with a stated reason).

The gate's SCOPE is now asserted too. It was globbed to `src/app/api/**/route.ts` plus `src/lib/api`, which claims "no route FILE leaks" rather than "no API response leaks"; five response builders sat outside it (`lib/auth/api-auth.ts`, `lib/auth/step-up.ts`, `lib/rateLimit.ts`, `lib/apiValidation.ts`, `lib/security/botId.ts`, `proxy.ts`, and route handlers outside `src/app/api`), and nothing failed when they landed there. `noRawResponseInCatchCoverage.test.ts` scans for every module that constructs a response and asks ESLint's own `calculateConfigForFile` whether the rule is switched on for it, failing on zero matches. Widening surfaced three real sites, all fixed: raw constructors inside catches in `api-auth.ts` and `apiValidation.ts`, and the webhook retry queue, which now carries a stated disable because it stores the error for replay rather than sending it. Separately, `/api/bridges/aseprite/execute` forwarded its BridgeResult verbatim on the SUCCESS path — `stdout`, `stderr` and an `error` built from `stderr`, carrying the child_process command line and the temp Lua script path — and now returns only `outputFiles`/`metadata`, with a test that asserts on the serialized body.

`redactSecrets` itself gains shapes for Meshy, ElevenLabs (`sk_` + hex — the OpenAI pattern is hyphenated and could never match it) and GitHub fine-grained PATs; an unanchored name pattern so `GITHUB_MODELS_PAT`, `ASSET_R2_ACCESS_KEY_ID` and `PGPASSWORD` are covered; a redacted marker at the depth bound instead of emitting the sub-tree unchanged; `Date`, `Error`, `Map` and `Set` preserved instead of collapsing to `{}`; `null` left as `null` instead of becoming `""`; upper bounds on every quantifier, matching the linear-matching invariant `sentryConfig` documents; and the environment list memoised behind a fingerprint that still invalidates under `vi.stubEnv`, so a Sentry event with hundreds of strings pays ONE derive (the regex test of every name plus the sort) instead of hundreds. The fingerprint itself still enumerates `process.env` per call, and `sentryConfig`'s `scrubString` calls the redactor per string leaf — the module comment now states that precisely rather than claiming "no allocation". Its docstring now states where redaction actually runs, and that BYOK keys for suno and hyper3d have no shape cover.

Also removes `src/lib/api/response.ts`, whose second exported `apiError` had a different envelope and no redaction, and makes the eight status-route messages reach the user. Two halves were needed: `useGenerationPolling` saw `!response.ok` and threw before reading the body, so a persistently failing status route showed a stalled progress bar for five minutes and then a bare "Generation timed out" — and reading the message was still not showing it, because `GenerationStatus` renders only while a job is pending/processing/downloading, so marking the last job failed unmounted the sole renderer at the instant the message was written. Every failure path now raises an error toast, asserted in `useGenerationPolling.test.ts`.
