Stop upstream provider text reaching clients, and enforce it with a lint rule (#9736). The generation clients fold the upstream **response body** verbatim into the thrown error (`Meshy status error (401): <body>`), and twelve routes returned that error's `message` in their response — so on the platform path, where the credential in play is the platform's rather than the user's, a provider that echoes key material in an auth-failure body would hand a platform secret to any signed-in user. Those routes now return fixed, actionable text and send the detail to Sentry; `/api/game/decompose` still returns its safety-filter reason, narrowed by a typed `PromptRejectedError` rather than by a message prefix any upstream error could also produce.

Enforcement is a local ESLint rule, `spawnforge/no-raw-response-in-catch` (`web/eslint-rules/`), applied to `src/app/api/**/route.ts` and the shared response builders under `src/lib/api/`. An earlier source-scanning version of this gate was defeated by eleven ordinary shapes — `err.toString()`, `err.response.data`, an `if` instead of a ternary, a destructure, a helper-built body, `new NextResponse(JSON.stringify(...))`, a header set after construction, an assignment to an outer `let`, `parts.push()` then `join`, a promise `.catch()` callback, and a plain `new Response(String(err))` — so it is deleted rather than kept as a weaker second gate. The rule forbids the SITE instead of the assembly: no `NextResponse.json` / `Response.json` / `new NextResponse` / `new Response` anywhere inside a catch scope, no caught value escaping into a binding declared outside the catch, and no caught value reaching a redacting constructor except inside an `instanceof`-narrowed branch. All eleven shapes are RuleTester cases.

That is also what makes `redactSecrets` real: 126 catch-path responses across 77 files now go through `createErrorResponse` / `apiError` / the new `redactedJson`, where previously 89 of 101 route files built error bodies with a raw `NextResponse.json` and the "net" covered none of the routes that had the defect. The rule found two live issues on its first run: `/api/admin/moderation/bulk` returned a database error's message inside a 200 body, and `/api/projects` reads a numeric field off its own error (waived in place with a stated reason).

`redactSecrets` itself gains shapes for Meshy, ElevenLabs (`sk_` + hex — the OpenAI pattern is hyphenated and could never match it) and GitHub fine-grained PATs; an unanchored name pattern so `GITHUB_MODELS_PAT`, `ASSET_R2_ACCESS_KEY_ID` and `PGPASSWORD` are covered; a redacted marker at the depth bound instead of emitting the sub-tree unchanged; `Date`, `Error`, `Map` and `Set` preserved instead of collapsing to `{}`; `null` left as `null` instead of becoming `""`; upper bounds on every quantifier, matching the linear-matching invariant `sentryConfig` documents; and the environment list memoised behind a fingerprint that still invalidates under `vi.stubEnv`, so a Sentry event with hundreds of strings no longer re-enumerates `process.env` once per string. Its docstring now states where redaction actually runs, and that BYOK keys for suno and hyper3d have no shape cover.

Also removes `src/lib/api/response.ts`, whose second exported `apiError` had a different envelope and no redaction, and makes the eight status-route messages reach the user: `useGenerationPolling` saw `!response.ok` and threw before reading the body, so a persistently failing status route showed a stalled progress bar for five minutes and then a bare "Generation timed out".
