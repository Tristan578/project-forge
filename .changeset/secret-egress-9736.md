---
"web": patch
---

Stop upstream provider text reaching clients, and put the control on the response path itself (#9736). The generation clients fold the upstream **response body** verbatim into the thrown error (`Meshy status error (401): <body>`), and twelve routes returned that error's `message` in their response — so on the platform path, where the credential in play is the platform's rather than the user's, a provider that echoes key material in an auth-failure body would hand a platform secret to any signed-in user. Those routes now return fixed, actionable text and send the detail to Sentry; `/api/game/decompose` still returns its safety-filter reason, narrowed by a typed `PromptRejectedError` rather than by a message prefix any upstream error could also produce.

**The guarantee is a runtime chokepoint, not a lint rule.** `withEgressGuard` (`web/src/lib/security/egressGuard.ts`) wraps all 102 App Router handlers and, before a response is returned, redacts the body (JSON parsed and re-serialised, other text redacted as text), every response header value, every `Set-Cookie`, and the `Location` of a redirect. That closes the header, cookie and redirect channels structurally — no dataflow analysis is involved. However the body was assembled, it passes through one function. Enforcement that every route is wrapped is a SHAPE check a parser can answer with certainty: `egressGuardCoverage.test.ts` walks every `src/app/**/route.ts` through the TypeScript parser and names any exported HTTP method that is not a `withEgressGuard(...)` call, failing closed on zero files.

Three review boards defeated three successive static designs before this. The first enumerated how a body was ASSEMBLED and lost to eleven ordinary shapes. The second forbade the SITE and lost to sinks the list did not name. The third tracked the caught value and reported where it CROSSED OUT of the catch scope, claiming that crossing out is a closed set — and lost to one-liners: `const sink = cache; sink.set('last', err.message)` aliasing a module-scoped Map, `const R = NextResponse`, a hoisted `function detail() { return String(err); }`, a tagged-template SQL write, and `yield`. The escape check compared NAME scope against reachability, so a single `const` silenced every escape the earlier boards had pinned. A hand-written static analysis over an open-ended language is the wrong primitive for a property that has to hold.

`spawnforge/no-raw-response-in-catch` is KEPT and demoted to what it is: early feedback in the editor for the common shapes, explicitly not the guarantee. Its docblock now says so and lists what it cannot see (`Promise.allSettled`, callback parameters, a tainted receiver, the non-throwing path, name collisions across nested scopes, the 12-pass fixpoint cap). The pass-3 shapes above are nonetheless closed and pinned by named RuleTester cases: receiver locality is now decided by what a binding RESOLVES to rather than by where its name was declared, local and namespace aliases of the raw constructors are resolved, the site ban is unconditional (a single `typeof err` in the arguments used to suppress it), tagged templates and `yield` are classified, and a hoisted function or class that closes over the caught value is tainted.

Redaction is also now genuinely on every response rather than only where a route remembered a sanctioned constructor: 126 catch-path responses across 77 files go through `createErrorResponse` / `apiError` / `redactedJson`, and the guard runs underneath all of them. `noRawResponseInCatchCoverage.test.ts` asks ESLint's own `calculateConfigForFile` whether the rule is switched on for every module that constructs a response, failing on zero matches. Widening the glob surfaced three real sites, all fixed. Separately, `/api/bridges/aseprite/execute` forwarded its BridgeResult verbatim on the SUCCESS path — `stdout`, `stderr` and an `error` built from `stderr`, carrying the child_process command line and the temp Lua script path — and now returns only `outputFiles`/`metadata`.

Two defects the runtime tests found, both real. **Percent-encoding defeated every credential shape**: they are anchored on a word boundary, and in `?e=invalid%20key%20sk-ant-AAA` the character before `sk-ant-` is the `0` of `%20`, so a redirect `Location` and a `Set-Cookie` value — the two channels the guard exists to close structurally — were passing the key through verbatim. `redactSecretsAll` gains an opt-in `percentAware` mode that matches a decoded view and splices the placeholder back into the raw string at mapped offsets, leaving the surrounding encoding byte-for-byte intact; it is off by default, so the Sentry path and the response constructors are unchanged. **Thirteen regex passes per string leaf** cost real time once the guard put redaction on every response; the shapes are now derived into one alternation that preserves their documented precedence, and the environment secret list is derived once per response rather than once per header value. Figures are below, from a committed harness.

`redactSecrets` itself gains shapes for Meshy, ElevenLabs (`sk_` + hex — the OpenAI pattern is hyphenated and could never match it) and GitHub fine-grained PATs; an unanchored name pattern so `GITHUB_MODELS_PAT`, `ASSET_R2_ACCESS_KEY_ID` and `PGPASSWORD` are covered; a redacted marker at the depth bound instead of emitting the sub-tree unchanged; `Date`, `Error`, `Map` and `Set` preserved instead of collapsing to `{}`; `null` left as `null` instead of becoming `""`; upper bounds on every quantifier, matching the linear-matching invariant `sentryConfig` documents; and the environment list memoised behind a fingerprint that still invalidates under `vi.stubEnv`.

Two gaps are stated rather than implied, and pinned as gaps by tests so nobody reads silence as coverage: a 2xx `text/event-stream` body streams through unredacted (buffering it would stall `/api/chat`, which streams as its core product path — its headers are still redacted, and any status >= 400 is always buffered and redacted), and an uncaught throw from a handler is re-thrown rather than converted, so Next.js renders its own error response and `instrumentation.onRequestError` and Sentry keep firing.

Also removes `src/lib/api/response.ts`, whose second exported `apiError` had a different envelope and no redaction, and makes the eight status-route messages reach the user. Two halves were needed: `useGenerationPolling` saw `!response.ok` and threw before reading the body, so a persistently failing status route showed a stalled progress bar for five minutes and then a bare "Generation timed out" — and reading the message was still not showing it, because `GenerationStatus` renders only while a job is pending/processing/downloading, so marking the last job failed unmounted the sole renderer at the instant the message was written. Every failure path now raises an error toast, asserted in `useGenerationPolling.test.ts`.

**A fourth review board found the design above shipping a blocker of its own, and it is worth stating plainly.** Redacting every response meant parsing, walking and re-serialising every response — and that carried `redactSecrets`' `MAX_DEPTH = 8` onto the success path, where it replaced any sub-tree past eight levels with the literal string `[REDACTED: nesting depth limit]`. At `{game:{sceneData:{entities:[{...}]}}}` an entity sits at depth 4, so a tilemap layer's `tiles` (`Vec<Option<u32>>`), a skeleton bone's `localPosition` (`[f32; 2]`) and an animation track's `keyframes` all land at or past the bound. Published games came back undeserialisable from `GET /api/play/[userId]/[slug]`, the editor wrote the truncated scene back on the next save, and `/api/user/export-data` handed the user a GDPR export with holes in it. Silently — no status change, no log. The bound was a correct fail-closed choice on the ERROR path this module was written for, where truncating a diagnostic costs nothing; moving it onto every 200 body without revisiting it is lessons-learned #1. The "byte-for-byte" test could not see it, because its fixture was `{ ok, items:[1,2,3], nested:{ a, b } }` — two levels, small integers, nothing a round-trip or a depth bound could damage (lessons-learned #11).

**The fix is a fast path, and it closes the lossiness and most of the latency at the same time.** The guard now SCANS the raw text of the body, every header value, every `Set-Cookie` and the reason phrase — one linear pass each, no `JSON.parse`, no tree walk. When nothing matches, which is the overwhelmingly common case, it returns the handler's own `Response` object untouched: same bytes, same headers, same `statusText`. So every round-trip loss the board reproduced simply does not happen on a body that contains no secret — pretty-printing destroyed on the `export-data` attachment, integer-like keys reordered, integers past 2^53 rounded, `1e400` turned into `null`, `-0` into `0`. `hasCandidate` is a strict over-approximation of the rewrite and reads the same environment list and the same shape alternation off one context, so the scan and the rewrite cannot drift apart.

**Depth is now unbounded**, and the traversal is iterative over an explicit stack so it is not bounded by the JS call stack either — a recursive walk would have thrown `RangeError` at roughly ten thousand frames, a limit nobody chose and no test named. Cycles are caught by ancestor identity and replaced with `[REDACTED: circular reference]`, the only serialisable answer; a DAG (one tileset referenced by two entities) is data and survives. The only remaining bound is `MAX_REDACTION_NODES`, which THROWS: the guard answers with its fixed 500 rather than serving a truncated body as if it were the real one.

**Two production breaks the board reproduced, both closed.** `ASSET_R2_ACCESS_KEY_ID` matched the secret-name pattern on the word KEY, and its value is embedded verbatim in every SigV4 presigned URL as `X-Amz-Credential=<AKID>/...`; the guard rewrote the `Location` of `/api/marketplace/assets/[id]/download`, R2 answered 403 `InvalidAccessKeyId`, and every paid asset download failed with nothing surfaced to the buyer. An access key id is a public identifier — SigV4 exists so it can travel in the clear — and the paired `..._SECRET_ACCESS_KEY` is still removed. Separately, `/\bforge_[0-9a-f]{32}\b/` could never match a real key: the route mints `randomBytes(32).toString('hex')`, which is 64 hex characters, and `{32}` cannot backtrack so the trailing `\b` always failed. It was listed as coverage for the one credential class this module can name with certainty and provided none. Correcting it to `{64}` is not sufficient on its own, because `POST /api/keys/api-key` returns the key in its 200 body for the one-time display that is the point of creating one — so the shape is corrected AND scoped to status >= 400 and the Sentry path.

Also: an absent `Content-Type` on a success status is no longer treated as textual, which stopped the guard buffering binary bodies, UTF-8-decoding them and replacing every byte >= 0x80 with U+FFFD (a 10-byte PNG header came out at 16); `statusText` is redacted rather than copied through, so the HTTP reason phrase is not a fourth client-visible channel; and a `__proto__` key is kept as data instead of being swallowed by `Object.prototype`'s setter.

**The enforcement walk had two blind spots.** It matched `entry === 'route.ts'`, but Next.js routes `route.js`, `route.jsx`, `route.mjs` and `route.tsx` identically — and the fail-closed floors (`> 90 files`, `> 100 methods`) are satisfied by the existing 102 `.ts` routes however many non-`.ts` routes exist, so a handler in any other spelling was invisible to the only enforcement the guard has. It now matches all five and asserts the discovered extension SET. And the analyser accepted the wrapper on identifier TEXT alone, so `const withEgressGuard = (h) => h;` passed the gate — the identical aliasing class that defeated review passes 1-3, reappearing in the half of the design that replaced them. The name now has to RESOLVE to an import from `@/lib/security/egressGuard`.

**Non-route response producers are named rather than implied.** `src/app/sitemap.ts`, `src/app/robots.ts` and the four `opengraph-image.tsx` files are first-party code the framework merely invokes, so "any response produced by the framework itself" did not describe them and the old wording invited a reader to infer coverage that does not exist. They are listed in KNOWN GAPS and pinned as a set by the coverage test, so adding one is a decision rather than a silent extension of the gap.

**The latency figures now come from a committed harness** (`web/scripts/bench-egress-guard.ts`), which prints node version, platform, CPU and env-key count alongside every number — the previous figures had no artifact anywhere in the diff, and were taken on a 13 KB listing rather than on the bodies that actually pay. Measured on Node 24.5.0, win32 x64, Ryzen 7 3800X, 200 iterations after 30 warmup:

| body | bytes | added |
|---|---|---|
| error envelope | 41 | +0.215 ms |
| community listing | 10,402 | +0.275 ms |
| published scene, 400 entities, no escapes (fast path) | 349,983 | +2.361 ms |
| same scene with JSON escapes and no secret (fast path) | 350,038 | +4.528 ms |
| same scene with a secret at depth 8 (match path) | 350,051 | +15.617 ms |

The fast path is what essentially every request pays; the match path is paid only by a response that actually carries a credential, and it is the parse-walk-reserialise the previous design imposed on all of them.

**Error toasts were carrying developer strings.** `failJob` promoted `No result URL`, `No texture maps` and `Downloaded file is not a valid GLB model` from a dropdown that is closed by default to the primary user-facing channel; the store still keeps the real diagnostic and the toast now gets fixed, actionable text for internal failures, passing through only messages a server route wrote for the user. It also used `showError`, whose 4 s auto-dismiss makes a terminal failure unrecoverable on a job that ran for up to five minutes in the background — `showPersistentError` is what `lib/toast.ts` documents for that class — and passed no toast id, so N concurrent timeouts stacked N identical toasts.

**A FIFTH board found the fast path unsound in exactly the scenario this feature exists for, and it is the most important defect in the whole change.** `hasCandidate` scanned the SERIALISED body; `redactValue`, the rewrite it claimed to over-approximate, ran on the PARSED leaves. On the wire a newline inside a string is backslash-then-`n`, and `n` is a word character, so the `\b` every credential shape is left-anchored on could not match. `{"error":"Meshy status error (401): Unauthorized\nmsy_… is not valid"}` — the literal shape of the Meshy auth failure #9736 was opened for — scanned CLEAN, the guard took byte identity, returned the handler's own bytes, and the client's `JSON.parse` restored the credential intact. The environment half failed identically: `text.includes(value)` ran on escaped bytes, so any secret containing a quote, a backslash or a newline (every PEM `*_PRIVATE_KEY`, a `PGPASSWORD` with a quote — both selected by `SECRET_NAME_PATTERN`) was never found on the wire and always found after parse. `textHasCandidate` now scans a JSON-unescaped view of the text alongside the raw text (gated on the text containing a backslash at all, so a body with none pays one `indexOf`), which restores every leaf and every key verbatim inside the scanned view; the characters a leaf gains around it there are non-word, so a boundary that held inside the leaf still holds. The invariant is now stated as the composition the guard actually performs — `JSON.stringify(redactValue(V)) !== JSON.stringify(V)` implies `hasCandidate(JSON.stringify(V))` — and swept over a corpus of escaped forms (`\n \r \t \f \b \" \\` and `\uXXXX`, plus env values containing a quote, a backslash, a newline and a tab) rather than asserted on one example. The test that had guarded this compared `hasCandidate(s)` against `redactText(s)` on the SAME string, a pair the guard never evaluates and which is nearly trivially true, with no JSON escape anywhere in its corpus — which is why four boards passed over the hole (lessons-learned #1 and #11).

**Object and Map KEYS were never redacted**, so a credential in key position survived even on the path the guard had already decided to rewrite: `{"msy_…":"invalid"}` made the scan say MATCH, bought the whole parse/walk/re-serialise round trip, and re-emitted the key unchanged — the lossy path AND the leak, reported as a rewrite. `openContainer` now runs plain-object and `Map` keys through the redactor, and two keys that redact to the same placeholder are disambiguated (`[REDACTED]`, `[REDACTED] (2)`) in source key order rather than one silently overwriting the other.

The added scan has a measured cost and it is stated rather than buried: a 350 KB body with **no** backslash is unchanged (+2.361 ms vs +2.270 ms before), and the same body with escapes in one script source roughly doubles (+4.528 ms vs +2.388 ms), because it is copied once and scanned a second time. Narrowing that to windows around escape sites is possible and is deliberately not taken — it is a new place for an off-by-one to become a leak. The match path grew from +14.110 ms to +15.617 ms, which is key redaction, and is paid only by a response carrying a credential. A byte-identity test on a large realistic body full of escapes and no secret asserts object IDENTITY, so the fix cannot have been "route everything down the slow path".

Also from the fifth board: `MAX_REDACTION_NODES`' headroom argument cited `scripts/bench-egress-guard.mjs` (a file that does not exist) and "~190 KB / ~34k nodes" (a figure this change's own harness contradicts) — the fixture is 349,983 bytes and walks 38,412 nodes, both now asserted against the exported constant via a new `lastNodeCount()` on the pass, and the previous headroom test could not have failed for any budget above 1001. The `event-stream` carve-out that keeps `/api/chat` streaming was justified by a citation to `node_modules` with a caret-ranged dependency and pinned only by hand-written mocks, so it now calls the real `ai` `createUIMessageStreamResponse()` and asserts its actual `content-type` against `isTextualContentType`. The `CLIENT_SAFE_ERRORS` allowlist comment cited `EmptyArtifactError` at `lib/api/errors.ts`, where the class does not appear; it lives at `lib/generate/emptyArtifactError.ts`. The comment that caused the never-matching `forge_[0-9a-f]{32}` pattern ("32 random hex chars" above `randomBytes(32).toString('hex')`) is corrected at its source. `showPersistentError`'s dedupe `id` and `failJob`'s `userFacing: false` branch — both introduced by this change, neither covered — now have tests. And the eight status routes' messages (`Texture generation produced no maps` and siblings) were still developer register with no next step, which falsified `failJob`'s premise that a server route's message is written for the user by definition — that string reaches a persistent toast a beginner cannot act on. The base sentences are a deliberately synchronised catalogue (`emptyArtifactError.test.ts` scans the whole tree so the submit-time and poll-time paths read identically), so the fix is a SUFFIX rather than a rewording: `withRetryGuidance` (`lib/generate/retryGuidance.ts`) is applied by the eight status routes and by `pollProviderStatus`, mirroring what `createGenerationHandler`'s `emptyArtifactResponse` already does on the submit-time path. It deliberately does not promise a refund, because the poll-time path does not know whether one happened.
