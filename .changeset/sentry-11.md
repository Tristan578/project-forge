Bump `@sentry/nextjs` and `@sentry/profiling-node` from 10.75.0 to 11.0.0 together (Sentry ships them as a matched pair; `sentry-regressions.test.ts` pins both to the same declared range and the same locked version, so neither could bump alone). The three `Sentry.init` configs (server, edge, client) are migrated to the v11 option surface: `dataCollection.queryParams` is renamed `urlQueryParams` (still opted out, so the exhaustive F03/F04 PII opt-out is unchanged); `enableLogs` is removed because v11 has no such option — logs ship whenever `Sentry.logger.*` is called, which makes the `beforeSendLog: scrubSentryLog` pin the only control on that pipeline; and `streamGenAiSpans` plus `vercelAIIntegration({ enableTruncation })` are removed because v11 always streams gen_ai spans and never truncates them (prompt/completion content is still withheld by `dataCollection.genAI`). The regression suite now pins that no config carries `enableLogs` at all. The root lockfile is regenerated for the new transitive dependency set.

v11 also makes span streaming the default, under which `beforeSendTransaction` is never called, so the transaction scrubber stopped covering spans. A new `scrubSentrySpan` (in `sentryConfig.ts`, built on the same `scrubString` / `deepScrub` / URL-query primitives) is wired as `beforeSendSpan` in all three configs: it strips query strings and fragments from URL attributes (`url.full`, `http.url`, `http.target`), replaces `url.query` / `http.query` / fragment attributes, redacts sensitive-key attributes and credential-shaped values in the span name, attributes and link attributes. `beforeSendTransaction` stays wired in the server and edge configs for the static lifecycle (selectable on Node and Edge by `SENTRY_TRACE_LIFECYCLE=static`), and is removed from the browser config, which cannot reach that lifecycle and where v11 would otherwise print a console warning on every page load. `scrubSentrySpan` also redacts `user.ip_address`, which v11 stamps onto streamed spans from the scope. The `dataCollection` opt-out now also sets `databaseQueryData`, `graphQL` and `queues` to `false` (all default-ON in v11), and the regression suite derives the required field list from the installed `DataCollection` type instead of a hand-written list.
