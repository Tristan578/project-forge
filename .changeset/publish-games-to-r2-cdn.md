Published games are now mirrored to Cloudflare R2 object storage on publish and served from that CDN-backed bundle on the player page. When `PUBLISH_TO_R2` is enabled (it defaults on wherever an `ASSET_BUCKET_NAME` is configured), publishing writes the game's scene data to a version-scoped object at `games/{userId}/{slug}/v{version}/bundle.json` and records that key on the game row; the `/play` route then reads the bundle for the row's own version first for faster, globally-cached loads. Version-scoped keys make each publication an immutable object — a republish writes a new version rather than overwriting the live one, so a failed or concurrent write can never corrupt the bytes an already-committed row points at, and `/play` verifies the bundle's manifest matches the row before serving it. The write and the read are both fail-open — any R2 outage, missing object, or stale/mismatched bundle logs to Sentry and transparently falls back to the existing Postgres-served scene data, so publishing and playing keep working with object storage entirely absent. A republish best-effort deletes the superseded version's object, and account deletion sweeps every published game's bundle key so nothing is orphaned in R2.
