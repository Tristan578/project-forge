# Gotchas — the generated Codex CLI surface

Its own file, not an entry in `gotchas-build-ci.md`, because it has to load where its
SOURCES are edited (skills, agents, hooks) and that file is far too large to load there.

- **Codex CLI surface drift: edit a skill, an agent or a hook under `.claude/` without regenerating and `Agentic Config Sync` goes red.** The FIFTH generated-artifact sync gate, and the one whose sources are the files agents edit most. The project skills under `.agents/skills/`, `.codex/agents/*.toml`, `.codex/hooks.json` and `.codex/hook-conditions.json` are GENERATED from `.claude/skills/`, `.claude/agents/*.md` and the `hooks` block of `.claude/settings.json` by `tools/agentic-sync/port.mjs` (#9745). They replaced a hand-copied port that rotted inside a week — 143 references to `.Codex/rules` and friends (directories that do not exist), 26 of 39 hooks wired, copies already drifted — and was quarantined in `.gitignore`.
  - **Detection / wiring:** `scripts/check-codex-port.sh` runs the generator in `--check` mode inside the `agentic-sync` job, gated on ci-gate's `needs-agentic`, whose filter names the SOURCES and everything the check READS (`.claude/skills|agents|rules|hooks|tools/`, `.claude/settings.json`, `.claude/CLAUDE.md`, `.agents/skills/`, `.codex/`, `.github/`, `.mcp.json`) — a filter naming only the generated side would let a skill edit merge with a stale mirror. It reports `missing`/`stale`/`orphan`/`extra`/`mode` (drift, in both directions), `modified` (a path that left the plan but no longer matches what the tool wrote — never deleted, stays reported until a person settles it), `untracked` (a source file git does not track and does not ignore — it was not mirrored, and is about to be committed), `ref` (a path under `.claude/`, `.codex/`, `.agents/` or `.github/` named in any `.codex/` file that does not exist — other roots such as `docs/` are NOT resolved — CASE-EXACTLY — `existsSync('.Codex/rules')` is true on a case-insensitive filesystem) and `mcp` (`.mcp.json` and `.codex/config.toml` declare different server names; Codex never reads `.mcp.json`). Exit 2 = could not run, including the deliberate hard errors: a hook EVENT, SCRIPT, or group/handler KEY in `.claude/settings.json` that `tools/agentic-sync/port.json` does not classify. That is the point — Claude Code adding a hook key must not silently change what Codex enforces. Unit-tested by `scripts/__tests__/check-codex-port.test.sh` (hermetic via `CODEX_PORT_ROOT`; never set in CI, and the suite asserts that).
  - **Fix any drift:** `git add` any NEW source file first — on every platform. Only files git tracks are mirrored, so a brand-new `SKILL.md` or skill script is reported as `untracked:` and `--write` exits 1 until it is staged; adding a skill is the commonest flow and the one-step recipe fails it on the first try. Then `node tools/agentic-sync/port.mjs --write`, then commit everything it regenerates WITH the source change (`.agents/skills/`, `.codex/agents/`, `.codex/hooks.json`, `.codex/hook-conditions.json`, `tools/agentic-sync/port.lock.json`). Never hand-edit a generated file; `ref` and `mcp` findings are fixed in the source or in the hand-written `.codex/` file, not by `--write`. **On Windows stage first, then run `--write` again:** `core.fileMode=false` stages every new file as 100644, and the generator can repair a mirrored script's executable bit only in an index entry that already exists (it prints how many it fixed).
  - **Adding a hook to `.claude/settings.json`:** decide what it means under Codex in the same change. A new event goes in `supportedEvents` or `unsupportedEvents` (with the reason); a script that cannot work there goes in `skipScripts`. Codex blocks ONLY on exit 2 with stderr, drops plain-text stdout, has no `async` and no `if` — `docs/guides/codex-cli-support-matrix.md` records each contract with the `openai/codex` source file it was read from, and what has NOT been confirmed in a live session.
- **A released file keeps its "GENERATED from" header until a person removes it.** When an agent is declared `agents.handAuthored` (or a skill `skills.independent`) the generator stops owning the file and drops it from the lock, but the text still says it is generated from a source that may no longer exist — and the `ref` check will say so. Taking a file over means taking its header over too.
- **Codex has TWO edit channels.** A patch can arrive as tool `apply_patch`, or carried in a shell command, which hooks see as `Bash` BEFORE Codex decides whether it is a patch. What Codex does not intercept runs in a real shell where `apply_patch` is a real executable on PATH (`arg0/src/lib.rs`) — that is the threat model. **Do not read the shell text.** Five recognisers here each failed open a different way: "contains `*** Begin Patch`" (blocked a plain `grep`), an envelope cut by regex, identifier-only heredoc delimiters, line continuations and leading redirects, then a deny-list for `cd` beaten by an earlier `<<`, `env -C` and a decoy heredoc, and an unquoted delimiter that let `$(…)` rewrite a path. Shell syntax is open-ended (lessons-learned #21). So a command with any line that looks like a file header has exactly TWO outcomes: ACCEPTED when the WHOLE command is `[cd <literal> &&] apply_patch <<'D'` … `D` (quoted delimiter, spaces/tabs only — a backslash-newline may join the first line, but not inside the cd target — nothing after) with a body Codex's parser accepts, else REFUSED unparsed. The known cost: a command that only writes text containing a patch is refused too. **Do not approximate Codex's patch parser either** — the adapter carries a line-for-line port of `parser.rs` + `streaming_parser.rs`, because three approximations each hid a file or misattributed added lines (column-0 headers; JavaScript's `trim()`, which keeps U+0085; trimming headers in every state, when inside an Update hunk Codex uses `trim_end()` only; a `(.+)` path regex that stops at U+2028). On the patch-tool channel a patch the port cannot parse is BLOCKED with the parse error — there was a fallback that showed whatever looked like a header, and it hid every disagreement between the port and Codex behind an exit 0 (a `\r\r` line, which Codex reads as empty because it strips a trailing CR twice, lost the added lines and the Move destination that way). When the supported Codex version moves, re-read those two files. The generator wires `PreToolUse` Edit/Write hooks for both channels; `PostToolUse` cannot see the second one at all (that call carries no command), and the exec tool's `workdir` is never visible to any hook. A new blocking check on file edits belongs on `PreToolUse`, and an `if` on such a hook must be a `Bash(word [word…] *)` condition or the generator stops.
- **An `if` never gates a blocking script under Codex.** Codex has no `if`; the adapter applies one only on NON-gating events (today: `post-push-resolve-comments.sh`, which would otherwise call `gh` after every shell command). On `PreToolUse` the script always starts and routes on the command itself — a filter in front of `block-main-commits.sh` skipped `g''it commit`, and the source's `Bash(git commit *)` never started it for merge, cherry-pick, revert or pull. So **a new blocking Bash hook MUST self-filter on the command** (as all five do today): under Claude Code the `if` saves it a start, under Codex nothing does.
