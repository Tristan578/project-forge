# Gotchas — Database, API, WASM & UI

## Database
- **Always use `queryWithResilience()`** — Only call `getDb()` inside the `queryWithResilience()` callback, never assign it to a standalone variable. Example: `queryWithResilience(() => getDb().select()...)`. ESLint `no-restricted-syntax` flags the `const db = getDb()` assignment pattern across `src/**`.
- **`onConflictDoUpdate` field completeness** — List EVERY mutable field in `.set()`. Missing fields keep original values.
- **Delete children before insert on upsert** — `db.delete(childTable).where(eq(parentId))` before inserting.
- **ZADD member uniqueness** — `Date.now()` collides in same ms. Use `` `${Date.now()}:${Math.random().toString(36).slice(2,8)}` ``.
- **CTE `FOR UPDATE` required for row locking** — Without it, concurrent requests snapshot the same pre-update value.
- **neonSql.transaction must include ALL related writes** — Never split claim and deduction across separate operations.
- **neon-http tagged template returns `Row[]`** — Use `.length` to check results, not `.rowCount`.
- **Circuit breaker trips at 5 consecutive transient failures** — Stays open for 30s, then half-open (1 probe). Non-transient errors (auth, syntax) don't count. Opening fires a Sentry alert (#8244); half-open/closed transitions are silent.
- **PGlite has no pgvector — the `.db.test.ts` harness rewrites vector DDL, so parity is name-existence only (PF-985 / #8977).** `@electric-sql/pglite` 0.5.x does not bundle pgvector, so replaying `drizzle/0010_graph_retrieval_nodes_edges.sql` verbatim throws `extension "vector" is not available` and breaks EVERY `*.db.test.ts` (the whole harness build fails, not just graph tests). `pgliteHarness.ts` `buildSchema()` applies a test-only DDL-rewrite shim before `pglite.exec`: strip `CREATE EXTENSION [IF NOT EXISTS] vector;`, `vector(N)` → `text`, and `USING hnsw (col vector_cosine_ops)` → `USING btree (col)` under the SAME index name (the regex stops at the closing paren so a trailing `WHERE "embedding" IS NOT NULL` partial-index predicate passes through untouched). This keeps table/column/index NAMES real so `schemaMigrationParity.db.test.ts` stays honest, but its scope is explicitly name-existence only — it does NOT diff column types or index predicates. Production keeps the real `vector(1536)` + HNSW; the rewrite never ships. Prod enables the extension via a dedicated `Enable pgvector extension` step in `cd.yml` that runs BEFORE `drizzle-kit push` (push does not emit `CREATE EXTENSION`).

## API & Security
- **usageId in generate route responses** — NEVER remove. Client needs it for async job refunds.
- **`refundTokens()` idempotency** — Check `metadata->>'refundedUsageId'` before crediting.
- **Generate status route: provider-success-with-no-artifact must map to `failed`, not `completed`.** A provider (Meshy/Replicate/Suno) can report success (`SUCCEEDED`/`succeeded`/`completed`) yet produce no downloadable artifact (empty GLB / `{}` maps / no audio URL). Mapping that unconditionally to `status: 'completed'` makes `useGenerationPolling` throw an uncaught "No result URL"/"No texture maps", stick the job in `downloading` for the full 5-min poll cap, then refund only via a generic timeout (#8757/#8758/#8759). Every `/api/generate/*/status` route must gate the result field (`resultUrl`/`maps`/…) on `mappedStatus === 'completed'` and report `failed` — with a specific `<Type> generation produced no <artifact>` message via a `succeededButEmpty` flag — when the artifact is absent (note `Object.keys(maps).length === 0` counts as absent; a truthy `{}` does not). The poller's `handleCompletion` catch also calls `triggerRefund(id)` so any completed-job download/import failure (expired URL, invalid GLB) refunds too, not just the status-route path.
  - **The status route is only HALF the surface — the same failure happens at SUBMIT time, and there it used to become an opaque 500.** A provider can answer the *initial* call with a 200 carrying no artifact (a missing prediction id, an empty `b64_json`). That throw lands in `createGenerationHandler`'s catch, which funnels every `execute` throw into `GENERIC_500_MESSAGE` — correct as a default, since raw `err.message` can carry env-var names and connection strings (#8597) — so the user got "something went wrong" for a condition the poll-time path names precisely. Throw `EmptyArtifactError` from `web/src/lib/generate/emptyArtifactError.ts` instead: the handler maps it to 503 with a message that is COMPOSED from two static nouns (never provider text), sets the `empty_artifact` metrics outcome, and appends the refund clause only when a deduction was really reversed.
  - **The two nouns are closed sets (`GENERATION_TYPE_LABELS`, `ARTIFACT_LABELS`), and that is load-bearing twice over.** A `string` param would accept a provider field as happily as a literal, defeating the "constructed, never passed through" property the 503 rests on; and it let the catalogue drift silently — a test built `('Texture', 'texture maps')` while the texture status route has always said `"…produced no maps"`. Same condition, two sentences, neither wrong enough to notice in review. `web/src/lib/generate/__tests__/emptyArtifactError.test.ts` scans every source file and fails on a sentence the arrays cannot build; adding a generation surface means adding its label there first.
  - **Still unmigrated (submit-time throws that remain opaque 500s):** `meshyClient.ts`, `spriteClient.ts`, `sunoClient.ts`. Migrating one is mechanical — swap the bare `throw new Error(...)` for `new EmptyArtifactError(<Type>, <artifact>)` and add the label to the arrays if it is a new surface.
- **`sanitizePrompt().filtered` without `.safe` check** — Always check `.safe` first.
- **A validator written with `.every` / `.some` FAILS OPEN on an array hole — the callback is never invoked for the missing slot, so the gate reports itself satisfied.** `[valid, , valid].every(pred)` is `true` with `pred` called twice, and `new Array(2).every(() => false)` is `true` with `pred` called zero times. `some`, `filter` and `forEach` skip holes as well; `map` skips the callback but **preserves the hole positionally**, so a gap survives every callback-shaped transform between the guard and the consumer. **No callback form closes this** — only an indexed read (a `for` loop or destructuring) sees every slot. Landed three instances in PF-1143 (#9232): the `movingPlatform` waypoint wire, `dialogueStore`'s `and`/`or` groups, and `effectSystem.isValidBinding`.
  - **Why the fail-open direction is the dangerous one.** These functions exist to reject. A hole in an AND-group made the group report itself satisfied; a hole in a type guard made it narrow to a type whose element type promises the gap cannot exist, so every downstream consumer is written against a lie. Consumers do NOT agree on hole behaviour: `for...of` does **not** skip a hole, it yields `undefined` — so the guard admits the array and the consumer throws on a property read, far from the cause.
  - **Two of these cannot be tested with the assertion you would reach for.** `kept.every(p => p.every(Number.isFinite))` *is* the bug and reports `true` on the offending input. Use `Array.from(arr)` (materializes each hole as an explicit `undefined`) and compare with `toEqual`, or assert the full expected content — never `toHaveLength`, which 64 sparse entries satisfy as readily as 64 real ones.
  - **A hole degrades into a `null` on the first serialization round trip:** `JSON.stringify` writes a hole as `null`, and `JSON.parse` can never produce a hole but readily produces `null`. So the same guard needs to reject both, and the `null` branch is the one reachable from imported/persisted JSON. Guard the CONTAINER too — `"conditions": null` or an omitted key makes `.length` throw one level up from the element check, the identical symptom from the identical source. Where several readers share one unvalidated `JSON.parse` boundary (`dialogueStore`'s `importTree` / `loadFromLocalStorage` feed five `nodes.find` sites, a `choices.filter` and a `for...of`), sanitize once at the boundary rather than bolting a guard onto each reader.
  - **`no-sparse-arrays` is NOT enabled in this ESLint config**, so an `eslint-disable-next-line no-sparse-arrays` above a deliberately-holed test fixture is a dead directive that `--max-warnings 0` then rejects. Use a plain comment saying the hole is the input under test. (`[a, , ]` has length 2 — a trailing comma after a hole is elision, not a third slot.)
- **Never spread LLM objects into engine commands** — Allowlist fields with `Number.isFinite()` guards.
- **`VERCEL_ENV` includes `'development'`** — Use explicit `=== 'production' || === 'preview'`.
- **`sanitizeSystemPrompt` truncates at 10k chars** — Use inline regex for scene context (can be 50k+).
- **`ToolLoopAgent.stream()` has no `onError`** — Use `result.toUIMessageStreamResponse({ onFinish })`.
- **Dynamic route `[name]` params need validation** — If POST validates name characters, PATCH/DELETE on `[name]` must validate too. Malformed percent-encoding (`%E0%A4%A`) passes Next.js decoding but should return 400 before DB queries.
- **`InstructionBlock[]` cache controls only fire on direct backend** — `createSpawnforgeAgent({ instructions: InstructionBlock[] })` joins blocks into a flat string when `isDirectBackend` is false. Adding `tier: 'long'` does nothing on the gateway/OpenRouter path. Per-user content (e.g. scene context) must include a per-user nonce inside the block text — Anthropic's prompt cache is keyed at the org level, so two users on the same Anthropic key share a cache namespace.
- **Chat SSE is the AI SDK v6 `UIMessageChunk` protocol — HYPHENATED types, v6 field names.** `/api/chat` streams via `result.toUIMessageStreamResponse(...)`, so `chatStore.streamOneTurn` must parse `text-delta {delta}` (NOT `text`), `reasoning-delta {delta}`, `tool-input-available {toolCallId, toolName, input}` (full parsed input — no JSON-string accumulation), `tool-input-error`/`tool-output-error {errorText}`, and a top-level `error {errorText}` (NOT `message`). Usage rides on `finish.messageMetadata.usage` via the route's `messageMetadata` callback — there is no standalone `usage` chunk in v6. Drift between route and client silently blanks every reply and runs zero tools (#8746). `web/src/test/utils/streamingTestUtils.ts` `makeChatSSEEvents` is the canonical wire shape; the parser is tested against exactly those bytes so a future protocol mismatch fails a test instead of shipping.
- **Sentry's server-side data scrubber redacts metric/tag/attribute VALUES, not just keys — a value containing `auth` ships as an unqueryable `[Filtered]`.** The project has `dataScrubberDefaults: true` with an empty custom field list, and that scrubbing happens SERVER-side, so no SDK option, `beforeSendMetric`, or local config turns it off — the value is redacted before it is ever indexed. Shipped live (PF-1053): the `outcome` attribute on `generation.request` used `unauthenticated` for 401, and every 401 sample landed as `outcome: [Filtered]`. Because `outcome` is the alerting dimension, that whole bucket became a facet no alert could ever fire on, and NOTHING in code review or the unit tests could see it — the emission side is perfectly correct.
  - **The trigger set is narrower than the documented default field list — probe, don't guess.** Measured against the live project: `auth`, `authorization`, `unauth`, `authenticated`, `reauth`, `password`, `passwd`, `secret`, `credentials`, `apikey`, `privatekey` are all redacted; `token`, `session`, `anonymous`, `no_session`, `insufficient_tokens`, `out_of_credits`, `bot_blocked`, `rate_limited`, `provider_unavailable`, `success`, `error` all survive intact. So `token` and `session` are NOT triggers on their own, and a naive "matches the default sensitive-fields list" assumption is wrong in both directions. Metric NAMES are not scrubbed (`generation.tokens_charged` survives).
  - **Distinguish the two scrubbers by their marker:** `[Filtered]` is Sentry's server-side scrubber; `[REDACTED]`/`[REDACTED_EMAIL]`/`[REDACTED_API_KEY]` come from this repo's own `web/src/lib/monitoring/sentryConfig.ts`. Seeing `[Filtered]` means the value left the process intact and was redacted on ingest — look at project settings, not at the SDK config.
  - **Guard new facet vocabularies with a test.** `GENERATION_OUTCOMES` in `web/src/lib/monitoring/generationMetrics.ts` is a runtime array (type derived from it) precisely so `__tests__/generationMetrics.test.ts` can iterate every value against the scrub pattern. Any new low-cardinality attribute vocabulary that alerts hang off needs the same treatment; a scrubbed value is invisible until someone queries production.
  - **Verify by querying the value back, not by confirming the metric arrived.** `metric.name:X` returning samples proves nothing about the facet — group by the attribute (`fields: ["outcome", "count()"]`) and read the actual values.

## WASM / CDN
- **WASM CDN same-origin fallback** — JS glue (`forge_engine.js`) and WASM binary (`forge_engine_bg.wasm`) are a coupled pair. Both MUST load from the same origin. Cannot load JS from CDN and WASM from same-origin. `getWasmBasePaths()` handles this.
- **`fetchWithRetry` 4xx handling** — The throw on 4xx is inside the try-catch loop. Must rethrow permanent errors explicitly or they get caught and retried as transient failures.
- **Same-origin WASM in production** — Requires CD pipeline to copy WASM artifacts to `web/public/` before `next build`. Already done in `cd.yml` lines 400-409.

## UI & Frontend
- **Dockview CSS class** — `.dv-dockview` (NOT `.dv-dockview-container`).
- **`aria-controls` requires target in DOM** — Use `<div hidden={!show}>` instead of conditional rendering.
- **SHADOWED_GLOBALS shared module** — `sandboxGlobals.ts` is single source of truth. Import, never duplicate.
- **Clerk `<SignIn>`/`<SignUp>` must be in `'use client'` files** — Server Component barrel export triggers SSR 500.
- **`<ClerkProvider>` goes INSIDE `<body>`, never around `<html>`** — `@clerk/nextjs` v7 is Clerk Core 3, whose upgrade guide requires the provider inside `<body>` and ties it to Next.js 16 cache components (both deploy roots use them). The outer placement is a hydration hazard, and it only misbehaves once a real key is present, so local key-less dev never catches it — `apps/docs` carried it unnoticed until Sentry flagged #9384. Mirror `web/src/app/layout.tsx`, which also guards on a well-formed key (`pk_test_`/`pk_live_` prefix) — required since 7.8.0 added `throwMissingPublishableKeyError()` to the keyless branch.
- **R2 engine CDN requires manual upload** — WASM files gitignored, use `wrangler r2 object put`.
- **`overflow: hidden` on `html` or `body` kills scrolling on EVERY page, and fails silently.** Per the CSS Overflow spec, when `html` is `overflow: visible` an `overflow` on `body` propagates to the **viewport** instead of clipping the body box. So a global `body { overflow: hidden }` in `globals.css` removes the scrollbar and disables wheel/trackpad input document-wide. It shipped live on every public marketing page (PF-1017 / #9037) and no automated check caught it, because **`window.scrollTo()` keeps working** — Playwright/jsdom assertions that scroll programmatically and read `scrollY` all pass. Only a real key/wheel event reproduces it. A surface that must own the full viewport (the editor) locks scrolling at **its own route segment** via `<ViewportLock>` (`web/src/components/layout/ViewportLock.tsx`), never globally. Guarded by `web/src/app/__tests__/public-scroll.test.ts`, which checks EVERY top-level `html`/`body` block (appending a later block is how the cascade reintroduces it), `packages/ui/src/tokens/theme.css` (`@import`ed by globals.css), and the `<body className>` in `app/layout.tsx` (a Tailwind `overflow-hidden` there does the same thing).
- **Full-viewport locks must be `h-dvh`, not `h-screen`.** `h-screen` is `100vh`, which on mobile Safari/Chrome resolves to the LARGE viewport (URL bar retracted). A `100vh` box in normal flow therefore overflows the visual viewport by the browser-chrome height and the surface becomes document-scrollable. `body { overflow: hidden }` used to mask this; nothing does now. `ViewportLock` and `EditorLayout`'s two roots all use `h-dvh` (pinned by the same test).
- **A CSP with neither a nonce nor `'unsafe-inline'` silently blanks the page — Next.js bootstraps App Router hydration with INLINE `<script>` tags.** `/play` shipped `script-src 'self' 'wasm-unsafe-eval'` and every published game rendered a blank/stuck page in production: the server HTML painted, every `self.__next_f.push(...)` bootstrap script was blocked, hydration never ran, and NOTHING threw server-side (PF-1018 / #9038). A CSP tightening that looks correct in review is only proven by a real browser load — `curl` sees the server HTML and reports success on a page no user can use.
  - **The nonce is a THREE-part contract, and each part fails silently alone.** (1) The proxy mints the nonce and sets it on the forwarded REQUEST via `NextResponse.next({ request: { headers } })` as BOTH `x-nonce` and `content-security-policy`, plus the enforcing `Content-Security-Policy` on the response. (2) Next.js reads the nonce off the *request* CSP header to stamp its OWN framework/bootstrap scripts — so dropping that request header, not just the response one, is what re-breaks hydration. (3) App-authored inline `<script>` tags are NOT auto-stamped; the page must read `(await headers()).get('x-nonce')` itself. A static `next.config.ts` `headers()` rule can never carry a per-request value, so the proxy is the only possible minter.
  - **Strip BOTH CSP header names from client input, not just the enforcing one.** Next resolves the nonce as `headers['content-security-policy'] || headers['content-security-policy-report-only']` (`app-render.js`), so leaving report-only unstripped lets a caller smuggle in a nonce of their choosing and have Next stamp it onto every framework script.
  - **`Buffer` is NOT a guaranteed global in the Edge runtime — use `btoa`.** The bare global came from a webpack `ProvidePlugin` (`webpack-config.js`, gated on `isClient || isEdgeServer`); Next 16 builds production with Turbopack, which never runs webpack plugins. Next's Edge sandbox exposes Buffer only through the `node:buffer` `NativeModuleMap`, i.e. via explicit import. A bare `Buffer.from(...)` in middleware is a latent `ReferenceError` that would 500 every request on that path.
  - **`type="application/ld+json"` is a CSP data block, not executable script** — `script-src` never gates it, so JSON-LD needs no nonce (verified in production: un-nonced ld+json tags produce zero violations). Don't cite it as evidence a nonce is working.
  - **A nonce forces dynamic rendering**, which is why the statically-cached marketing pages keep `'unsafe-inline'` instead. Only add a nonce to a route that is already dynamic (`/play` awaits `safeAuth()`).
  - **Repro against a PRODUCTION build, never `next dev`** — the dev server keeps `'unsafe-eval'`/inline for Fast Refresh, so the bug is invisible: `cd web && npm run build && npx next start`, then load `/play/<userId>/<slug>` in a real browser and check for CSP violations in the console.
